# Архитектура NexusPDF

## Слои

```
App.Desktop (WPF, MVVM)          — окна, view-модели, темы, локализация
   │
Application                      — OpenedDocument, SaveService, SearchService
   │
Domain                           — DocumentSession, PageRef, операции, Undo/Redo
   │
Pdf.Abstractions                 — интерфейсы движков и модели данных
   ▲
   ├── Pdf.Pdfium                — рендер/текст/компоновка (PDFium)
   ├── Pdf.Qpdf                  — структура/шифрование (qpdf, план: этап 3/6)
   └── Ocr.Tesseract             — OCR (план: этап 7)

Infrastructure                   — настройки, логи, атомарная запись,
                                   одиночный экземпляр, crash-сентинел
PdfWorker                        — каркас изолированного процесса (план: этап 3)
```

Правила зависимостей: `Domain` и `Application` не знают о WPF и о конкретных
PDF-SDK; движки видят только `Pdf.Abstractions`. UI получает движки через
интерфейсы (`IPdfRenderEngine` и т.д.), у необязательных движков есть
`IsAvailable`/`UnavailableReason` — недоступная функция скрывается, а не
имитируется.

## Модель документа

`DocumentSession` держит **логическую** структуру: список `PageRef`
(источник, номер страницы в источнике, добавочный поворот). Физический файл
не изменяется до сохранения. Все операции (поворот, удаление, перестановка,
вставка, дублирование) — обратимые команды над этим списком; `UndoRedoStack`
хранит их историю, признак «есть несохранённые изменения» считается по
счётчику версий (undo к сохранённой точке снимает признак).

Такой дизайн даёт бесплатно: перенос страниц между документами (PageRef может
указывать на чужой источник), извлечение подмножества, безопасность (ошибка
любой операции не трогает файлы).

## PDFium

- PDFium не потокобезопасен → все вызовы сериализуются на одном выделенном
  потоке (`PdfiumThread`), наружу — только `Task`.
- Документ открывается через **memory-mapped file** + `FPDF_LoadMemDocument`:
  юникод-пути обрабатывает .NET, страницы файла ОС подгружает лениво,
  большой PDF не копируется в управляемую кучу.
- Рендер — в пиновый BGRA-буфер (`FPDFBitmap_CreateEx`), из него создаётся
  замороженный `BitmapSource`.
- Сохранение — компоновка нового документа: `FPDF_ImportPages` (пакетами по
  источникам, порядок сохраняется), затем добавочные повороты
  (`FPDFPage_SetRotation` меняет метаданные, без растеризации) и
  `FPDF_SaveAsCopy` через колбэк записи.

## Сохранение без потери данных

`SafeFileReplace`: результат пишется во временный файл **в каталоге цели**
(тот же том → атомарная замена), затем повторно открывается движком и
проверяется (число страниц, размеры), и только после этого `File.Replace`.
Ошибка на любом шаге оставляет целевой файл нетронутым, временный файл
удаляется. После сохранения документ переоткрывается из результата
(история очищается — задокументировано).

Файл источника открывается с `FileShare.ReadWrite | Delete`, поэтому
сохранение «в себя» возможно при живом отображении в память.

## UI

- Просмотр: `ListBox` с `VirtualizingStackPanel` (пиксельная прокрутка,
  виртуализация Standard — контейнеры создаются/уничтожаются, что запускает
  ленивый рендер через attached-behavior и освобождение растра при уходе).
- Кэш растров — LRU с лимитом по байтам (настройка `RenderCacheMegabytes`),
  ключ: источник+страница+поворот+ширина в пикселях.
- Локализация — JSON-словари `Resources/i18n/*.json` (встроены в сборку);
  новый язык = новый файл. Смена языка применяется после перезапуска.
- Темы — словари брашей Light/Dark + системная (реестр
  `AppsUseLightTheme`), стили обращаются через `DynamicResource`.
- Несколько окон: `WindowManager`; вкладка переносится между окнами без
  переоткрытия документа.

## План изоляции (этап 3)

Рендер/OCR/сжатие недоверенных файлов переезжают в процесс `PdfWorker`
(именованные каналы + memory-mapped files, лимиты памяти/времени,
перезапуск после сбоя). Интерфейс `IPdfRenderEngine` не меняется — меняется
хост реализации.
