# Архитектура печати

Дата: 2026-08-15, версия 0.17.0.

## Главный принцип

Предпросмотр и печать используют **один рассчитанный `PrintJobPlan`**.
Отдельной упрощённой логики для картинки в окне не существует — не по
договорённости, а потому что такого кода нет. Разница между окном и бумагой
сводится к одному аргументу: DPI.

```
Настройки окна ─► PrintLayoutEngine ─► PrintJobPlan (листы в пунктах)
                                            │
                        ┌───────────────────┼───────────────────┐
                        ▼                   ▼                   ▼
                 SheetComposer 96 dpi  SheetComposer 300  SheetComposer 300
                        │                   │                   │
                 PrintPlanRenderer    PrintPlanRenderer   PrintPlanRenderer
                        │                   │                   │
                   предпросмотр        очередь Windows      файл PDF
```

## Модель

`PrintJobPlan` → `SheetPlan` (физический лист) → `PlacedPage` (страница на
листе). Все координаты — в **пунктах PDF** (1/72 дюйма), начало в левом
верхнем углу листа. Пиксели появляются единственный раз, в `SheetComposer`.

`PlacedPage` хранит и результат (`TargetRectPt`, `ClipRectPt`), и то, из чего
он получен (`SourceRectPt`, `Scale`, `RotationDegrees`, политика аннотаций,
причина растеризации). Благодаря этому тест проверяет геометрию, а окно
объясняет пользователю, почему содержимое обрезано.

Лицевая и обратная стороны листа — **разные** `SheetPlan` со ссылкой друг на
друга (`PairedSheetIndex`): так порядок дуплекса и буклета проверяется
тестами, а не сложенной стопкой бумаги.

## Ключевые решения и их причины

- **Непечатаемые поля запрашиваются для каждого формата отдельно.** Общей
  величины «на принтер» не существует; у OneNote поля A3 и Letter различаются
  вдвое. Из-за одной усреднённой величины содержимое уезжает под ролики.
- **Гигантский лист понижает DPI, а не обрезается.** Обрезанный растр
  напечатал бы половину страницы, и заметить это можно было бы только на
  бумаге. Фактический DPI возвращается в `ComposedSheet.Dpi`.
- **Обрезка выполняется переносом пикселей, а не рендером меньшего размера.**
  Иначе обрезанная страница печаталась бы сжатой — это разные вещи.
- **`PrintTicket` согласуется с драйвером** через `MergeAndValidatePrintTicket`:
  драйвер вправе поправить несовместимое сочетание, и работать надо с тем,
  что он вернул, а не с тем, что мы попросили.
- **Разрешения PDF перечитываются перед самой отправкой**, а не берутся из
  плана: между открытием окна и нажатием «Печать» документ в той же вкладке
  мог смениться.
- **Листы готовятся по одному в момент запроса** пагинатором — тысяча листов
  не оказывается в памяти целиком.
- **Enter не отправляет задание.** Кнопка «Печать» не назначена кнопкой по
  умолчанию: случайное нажатие в поле ввода не должно уводить на принтер
  сотню листов.

## Что нельзя сделать на этих движках

PDFium не отдаёт векторные команды наружу, поэтому размещение страницы на
листе — всегда изображение. Это ограничение движка, а не решение; подробности
и последствия — в [PRINT_KNOWN_LIMITATIONS.md](PRINT_KNOWN_LIMITATIONS.md).
