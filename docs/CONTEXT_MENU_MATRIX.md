# Матрица контекстных меню

Правая кнопка, долгое удержание пальцем и кнопка пера открывают ОДНО и то же
меню: оно собирается из реестра команд по виду выделения
(`ContextMenuComposer.Menus`).

Правило простое: в меню только то, что действительно работает. Виды выделения,
которых интерфейс пока не различает, дают пустое меню — правая кнопка там
просто ничего не открывает, а не показывает обманку.

## Что открывается и где

| Место | Вид выделения | Пункты |
|---|---|---|
| Пустое место страницы | `Nothing` | Выделить все · Страница целиком, По ширине, Фактический размер · Добавить текст…, Вставить изображение…, Заметка, Править текст · Редактировать область/страницу в Paint…, Печать этой страницы… · Свойства документа… |
| Выделенный текст | `Text` | Выделить маркером, Подчеркнуть, Зачеркнуть, Найти это в документе · Копировать · Заметка · Вымарать |
| Ссылка в документе | `Link` | Открыть ссылку · Копировать адрес ссылки |
| Миниатюра страницы (панель) | `Page` | Повернуть вправо/влево/на 180° · Дублировать · Извлечь в новый PDF…, Редактировать страницу в Paint…, Печать выбранных страниц… · Свойства страницы… · Удалить страницы |
| Страница в режиме систематизации | `Page` | то же самое, с учётом множественного выделения |
| Узел оглавления | `Bookmark` | Перейти к закладке |
| Вкладка документа | `Tab` | Сохранить, Сохранить как… · Печать…, Открыть вкладку в отдельном окне · Свойства документа… · Закрыть вкладку |

## Поведение, которое пришлось продумать

**Правая кнопка не снимает выделение текста.** Иначе к моменту показа меню
размечать было бы уже нечего.

**Попадание в выделение с допуском.** Строка текста при масштабе 50 % высотой
всего несколько точек. Требовать попадания пиксель в пиксель — значит отдавать
пользователю меню страницы вместо меню выделения, поэтому рамки строк
расширяются на 6×4 точки при проверке.

**Щелчок по миниатюре вне выделения делает её выбранной.** Иначе команда
молча применилась бы не к той странице, по которой щёлкнули. У боковой панели
выделение одиночное, у режима систематизации — множественное; код учитывает
оба, потому что WPF запрещает трогать `SelectedItems` в одиночном режиме
(на этом уже был отловлен сбой).

**Правая кнопка по вкладке сначала делает её активной.** Иначе «Сохранить» из
меню одной вкладки сохранило бы другую.

**Многоточие ставится автоматически** по признаку `OpensDialog`, а не вручную
в словаре: так его нельзя забыть в одной из точек интерфейса.

**Одна команда — разное поведение по контексту.** «Выделить маркером» и
«Вымарать» работают по выделенному тексту, если он есть, и как прежний
инструмент рамки, если выделения нет. Это одна команда с одним
идентификатором, а не две похожие.

## Сенсорный ввод

Долгое удержание (450 мс, сдвиг не больше 8 точек) открывает то же меню в
точке касания. Кнопка пера (barrel button) — тоже. Меню позиционируется по
точке касания, а не по последнему положению курсора мыши, которого у пальца
просто нет.

## Проверено глазами

- меню пустого места, выделенного текста, миниатюры и вкладки — снимки экрана
  в `scratchpad/ux`;
- «Выделить маркером» по выделенной строке: разметка появляется сразу, до
  сохранения, и видна в миниатюре;
- при плотности «Для пальца» строки меню становятся 44 точки высотой.
