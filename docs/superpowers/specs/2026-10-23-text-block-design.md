# Текстовый блок (этап 1 из 3): проект

Дата: 2026-10-23. Макет: [2026-10-23-text-block-mockup.html](2026-10-23-text-block-mockup.html).

## Зачем

Добавлять текст в NexusPDF сейчас неудобно. Надпись пишется в отдельном окне
и ставится щелчком; после этого её нельзя ни передвинуть, ни поправить —
только отменить. Строка одна, переноса нет, шрифтов восемь. На незаполняемых
бланках (судовые формы, бланки лоцманов, агентов) это главный сценарий:
вписать дату, ETA, имя в клетку таблицы.

Нужен уровень современных редакторов PDF (Acrobat Pro): щёлкнул — пишешь
прямо на странице, оформление под рукой, блок потом можно взять, передвинуть,
растянуть и поправить — в том числе после сохранения и повторного открытия.

Работа разбита на три этапа, этот документ — первый:

1. **Текстовый блок** (этот документ).
2. Заполнение незаполняемых бланков: клетка ищется по линиям вокруг щелчка,
   блок встаёт в неё; значки ✓ ✗ ● и обводка (Fill & Sign). Строится на
   блоке из этапа 1.
3. Правка существующего текста абзацами с переносом (Edit PDF).

Решение Артура: делать по максимуму, в этом порядке.

## Цели

- Инструмент **Text**: щелчок по странице — сразу курсор; протянуть рамку —
  блок заданной ширины с переносом по словам. Без отдельного окна.
- Несколько абзацев и строк: Enter — новый абзац, Shift+Enter — новая строка.
- Оформление **частей текста**: выделенный фрагмент получает свой шрифт,
  размер, начертание (Ж/К), подчёркивание, зачёркивание, цвет, верхний и
  нижний индекс, межбуквенный интервал.
- Оформление абзаца: выравнивание (влево, по центру, вправо, по ширине),
  межстрочный интервал.
- Блок: перетащить, растянуть ручками, повернуть (свободно и точно в панели),
  удалить (Delete), копия (Ctrl+D), сдвиг стрелками — как у остальных объектов
  сейчас (5 пт, с Ctrl — 1 пт), положение и размер в мм в правой панели,
  «Auto height» — высота по тексту, «Shrink to fit» — размер шрифта
  уменьшается, чтобы текст влез в рамку.
- **Плавающая панель** над блоком (шрифт, размер −/+, Ж/К/Ч/зачёркнутый,
  цвет, выравнивание, «⋯») и **правая панель свойств** с полным набором.
- **Любые установленные шрифты** Windows (системные и пользовательские) с
  поиском, недавними, шрифтами документа; шрифт без нужных букв или с
  запретом встраивания виден, но помечен (см. «Шрифты»).
- «Use as default style» — новые блоки пишутся этим стилем; запоминается.
- **Повторная правка после сохранения**: двойной щелчок по блоку, записанному
  NexusPDF, снова открывает его целиком — с абзацами, переносами и стилями.
- Тот же выбор шрифтов получает существующая правка строки (двойной щелчок по
  чужому тексту) — вместо нынешних восьми гарнитур.
- Отмена и повтор (Ctrl+Z / Ctrl+Y) для всех действий с блоком.

## Не цели этапа 1

- Поиск клетки бланка, значки ✓ ✗, обводка — этап 2.
- Правка чужого текста абзацами — этап 3. Блоки, записанные другими
  программами, остаются обычным текстом страницы.
- Маркированные и нумерованные списки, колонки, связанные блоки, текст по
  кривой, вертикальное письмо, проверка орфографии.
- Фон и рамка у блока (при необходимости рисуются фигурами).
- Аннотация FreeText (комментарий-надпись) — см. «Подходы».

## Анти-цели (провал, даже если «работает»)

- На экране одно, на печати или в другой программе — другое (перенос в
  другом месте, другой шрифт, квадраты вместо букв).
- Файл, который Acrobat, Chrome или Firefox открывают с ошибкой или пустым.
- Потеря набранного из-за щелчка мимо или переключения вкладки.
- Шрифт попал в PDF вопреки запрету автора шрифта.
- Подписанный документ после добавления блока теряет подпись (сохранение
  подписанных идёт дописыванием — как сейчас).
- Блок, изменённый другой программой, NexusPDF «восстанавливает» по старым
  данным и затирает чужую правку.

## Ограничения

- C# / .NET 10, WPF (`App.Desktop`), движок PDFium (`Pdf.Pdfium`), правила
  `docs/ARCHITECTURE.md`: движки видят только `Pdf.Abstractions`, Domain и
  Application не знают о WPF и SDK.
- Публичный репозиторий (AGPL-3.0): в коде, тестах и фикстурах — только
  выдуманные данные.
- Предупреждения в `src` — ошибки сборки; тесты PdfEngineTests/UnitTests
  должны идти и на Linux с `-p:EnableWindowsTargeting=true` (кроме того, что
  требует шрифтов Windows — такие тесты уже есть и помечены причиной).
- Старый `TextOverlay` используют штампы, колонтитулы, водяные знаки, сводка
  комментариев — он остаётся без изменений; блок — новый вид объекта.
- PDFium встраивает шрифт целым файлом (`FPDFText_LoadFont`), подмножества не
  делает: большие шрифты (CJK, десятки МБ) раздувают файл.

## Подходы (выбор хранения блока в файле)

1. **Текст страницы + скрытая метка с описанием блока.** Выбран Артуром.
   Блок записывается обычными текстовыми объектами страницы, все объекты
   блока помечены marked content с описанием блока. Везде выглядит и
   печатается одинаково, ищется и копируется; NexusPDF по метке узнаёт свой
   блок и открывает его для правки после сохранения; другие программы видят
   обычный текст.
2. **Аннотация FreeText.** Остаётся редактируемой рамкой и в Acrobat, но это
   комментарий: пропадает при печати «без комментариев», внешний вид зависит
   от программы. Для официальных бланков ненадёжно.
3. **Только текст страницы.** Проще всего, но после сохранения блок
   распадается на строки, правка блока возможна только после этапа 3.

## Что решено с Артуром

- Все три этапа, по максимуму, порядок: блок → бланки → абзацы.
- Хранение — подход 1.
- **Ввод выглядит точно как файл** (как в Acrobat): пока человек печатает,
  текст рисует та же раскладка, что пишет PDF; после завершения ввода ничего
  не «прыгает». Ради этого — собственный редактор, а не поле ввода Windows
  (выбор Артура, с пониманием, что это самая большая часть этапа).
- Интерфейс — по макету: инструмент Text, плавающая панель над
  блоком, правая панель (Font, Paragraph, Character, Box, Use as default
  style), выбор шрифта (поиск, Recent, In this document, All fonts, пометки),
  таблица действий из раздела 3 макета.
- Язык интерфейса — локализуется как вся программа (ru/en/uk).

## Как устроено (решения исполнителя, не согласовывались отдельно)

### Модель блока (`Pdf.Abstractions`)

`TextBlockOverlay : PageOverlay` — неизменяемая запись:

- рамка в отображаемых пунктах (`XPt, YPt, WidthPt, HeightPt`), поворот в
  градусах вокруг центра рамки;
- режим ширины: `AutoWidth` (щелчок — блок растёт вправо, без переноса) или
  `Fixed` (рамка — перенос по словам); `AutoHeight` (высота по тексту);
- абзацы: выравнивание, межстрочный интервал (множитель), фрагменты;
- фрагмент: текст + стиль (гарнитура, размер, Bold, Italic, Underline,
  Strike, цвет ARGB, сдвиг базовой линии: нет/верхний/нижний индекс,
  межбуквенный интервал в % размера);
- `BlockId` (GUID) — связь с уже записанными объектами страницы, если блок
  открыт для правки после сохранения (иначе пусто).

Для правки блока, уже лежащего в файле, — `TextBlockReplacement(BlockId,
TextBlockOverlay?)`: убрать объекты блока со страницы и (если не null)
записать новый. Удаление блока = замена на null.

Сериализация блока (для метки) — компактный JSON с версией формата.

### Решения после проверки проекта

- **Ленты инструментов из макета в программе нет** — она нарисована для
  наглядности. Инструмент Text — кнопка вместо нынешней «Add text» в группе
  правки и на быстрой панели; перестройка панелей не входит в этап.
- **Нет буквы в выбранном шрифте.** Символ пишется запасным шрифтом того же
  начертания (по порядку: шрифт по умолчанию, Arial, Segoe UI, первый
  шрифт каталога с этим символом); в редакторе такой символ подчёркнут
  пунктиром, в панели — пояснение. Квадратов в файле не бывает: фрагмент
  при раскладке делится на куски «один шрифт — один кусок». Шрифт фрагмента
  в модели остаётся выбранным пользователем; подстановка — свойство
  раскладки, а не модели.
- **Письменности со сложной вёрсткой** (арабская, иврит, деванагари и др. —
  требуют shaping и письма справа налево) в этапе 1 не поддерживаются: ввод
  таких символов не принимается, с пояснением. Латиница, кириллица, греческий,
  цифры и знаки — поддерживаются.
- **Текст не влезает при выключенном «Auto height».** Не обрезается (потеря
  текста недопустима): строки продолжаются ниже рамки, рамка помечается
  значком переполнения. Опция «Shrink to fit» уменьшает размер шрифта блока
  (шагом 0,5 пт, не меньше 4 пт), чтобы текст влез; этап 2 включает её для
  клеток бланков.
- **Стрелки** — как у всех объектов сейчас (5 пт, с Ctrl — 1 пт): одинаковое
  поведение важнее.
- **После повторного открытия** одиночный щелчок выбирает блок (перетащить,
  растянуть, удалить), как черновик.

### Шрифты (`Pdf.Abstractions` + `Infrastructure`)

`FontCatalog` заменяет закрытый список `PdfFontCatalog` (старый API остаётся
как обёртка для существующих вызовов):

- перечисляет `%WINDIR%\Fonts` и `%LOCALAPPDATA%\Microsoft\Windows\Fonts`
  (каталог задаётся извне — для тестов); `.ttf`, `.otf` с TrueType-контурами,
  `.ttc` (лица коллекции);
- читает таблицы `name` (семейство, начертание), `OS/2` (`fsType`), `cmap`,
  `hmtx`, `hhea`, `head`, `post` собственным небольшим читателем TrueType
  (без внешних зависимостей; таблицы — по спецификации OpenType);
- группирует файлы в семейства с четырьмя начертаниями; отсутствующее
  начертание — ближайшее имеющееся (как сейчас); синтетический курсив/жирный
  не делаются;
- пометки: «нет кириллицы» (по `cmap`), «нельзя встроить» (`fsType`
  Restricted License или только растр), «не поддерживается» (CFF-контуры,
  если PDFium их не встраивает — проверить); шрифт без кириллицы выбрать
  можно, при вводе отсутствующих букв — предупреждение сразу;
- лицо из `.ttc` для PDFium выделяется в отдельный TrueType-файл в памяти;
- кэш каталога (путь, размер, дата файла) — чтобы список открывался мгновенно;
- «In this document»: шрифты текстовых объектов документа (PDFium) с
  подстановкой: стандартные 14 (Helvetica→Arial, Times→Times New Roman,
  Courier→Courier New, Symbol/ZapfDingbats — как есть), прочие — по имени
  семейства без префикса подмножества; показывается, каким шрифтом напишется;
- «Recent» и «стиль по умолчанию» — в настройках приложения.

### Вёрстка (`Pdf.Abstractions`, без зависимостей от UI и SDK)

Один движок раскладки для предпросмотра, рамки, «Auto height» и записи в PDF
— иначе экран и файл разойдутся:

- ширины глифов — из `hmtx` через `cmap`, без кернинга и лигатур (PDFium
  их тоже не применяет);
- перенос по словам (пробел, дефис), слово длиннее строки режется по
  символам; Shift+Enter — принудительный перевод строки;
- высота строки = (ascender − descender + lineGap) × размер × межстрочный
  множитель, по самому крупному фрагменту строки;
- выравнивание по ширине — растягиванием пробелов (кроме последней строки
  абзаца);
- индексы — 0,65 размера со сдвигом базовой линии ±0,33 размера (как в
  Word); межбуквенный интервал — добавка к ширине каждого глифа;
- результат — список строк с позициями фрагментов в координатах блока
  (до поворота); детерминирован и покрыт тестами.

### Запись в PDF (`Pdf.Pdfium`)

- По раскладке: на каждый кусок строки с одним стилем — текстовый объект
  (`FPDFPageObj_CreateTextObj`, шрифт из кэша документа как сейчас), цвет,
  матрица с поворотом блока и пересчётом в систему координат страницы (с
  учётом `/Rotate`, как у нынешних оверлеев). Межбуквенный интервал и
  растянутые пробелы — отдельным позиционированием глифов или групп (если у
  PDFium нет установки Tc/Tw для объекта — проверить в API).
- Подчёркивание и зачёркивание — тонкие закрашенные прямоугольники цвета
  текста (толщина и положение — из `post`/`OS/2` шрифта).
- Метка: каждый объект блока получает marked content `NexusTextBlock` с
  параметрами `Id` (GUID блока), `V` (версия) и `R` (номер строки и куска);
  первый объект — ещё и `Data` (рамка, режимы, абзацы, стили фрагментов —
  **без самого текста**) и `Hash` (хеш текста, положения и стиля всех
  объектов блока). Через `FPDFPageObj_AddMark` /
  `FPDFPageObjMark_SetStringParam`.
- Текст в `Data` не хранится намеренно: при вымарывании или стирании области
  часть объектов исчезает, и копия текста в метке сохранила бы стёртое.
  Текст при повторном открытии собирается из самих объектов по `R`.
- Проверить, что метки переживают сохранение PDFium (генерация содержимого
  страницы) и повторное сохранение, полную перезапись и дописывание. Если не
  переживают — описание блока хранится в `/PieceInfo` страницы по `Id`
  (с тем же правилом «без текста»).
- Вымарывание и стирание области, задевшие блок, снимают с оставшихся
  объектов метку: блок становится обычным текстом.

### Повторная правка после сохранения

- При открытии страницы для правки ищутся объекты с меткой `NexusTextBlock`,
  группируются по `Id`; блок читается из `Data`.
- Проверка целостности: текст, положение и стиль объектов группы
  сравниваются с `Hash`; если
  блок менял кто-то другой (не совпало, части объектов нет) — блок не
  открывается как блок, а остаётся обычным текстом (правка строкой, как
  сейчас), с пояснением в строке состояния. Чужая правка не затирается.
- Двойной щелчок по такому блоку → тот же редактор; сохранение правки —
  `TextBlockReplacement`: объекты группы удаляются, блок пишется заново
  (с той же меткой и тем же `Id`).

### Редактор на странице (`App.Desktop`)

- Инструмент **Text** в ленте (вместо команды «Add text» с окном
  `AddTextDialog`; окно удаляется).
- Ввод — **собственный редактор** (WPF-элемент поверх страницы), который
  рисует текст по общей раскладке: глифы — `GlyphRun` из тех же файлов
  шрифтов в тех же позициях, что запись в PDF, в масштабе страницы. Что видно
  при вводе — то и окажется в файле, до перевода строки и межбуквенного
  интервала. После завершения ввода блок рисуется через запись в PDF, как
  черновики сейчас; расхождения быть не должно (проверяется тестом).
- Редактор сам реализует:
  - курсор (мигание по системной частоте, положение по раскладке), выделение
    мышью (щелчок, протягивание, двойной — слово, тройной — абзац, Shift+щелчок)
    и клавиатурой (стрелки, Home/End, Ctrl+стрелки по словам, Ctrl+A,
    Shift-варианты, PageUp/PageDown внутри блока);
  - ввод через `TextInput`/`TextComposition` с поддержкой IME (окно
    составления у курсора), раскладок и Alt-кодов; Backspace/Delete,
    Ctrl+Backspace/Delete по словам;
  - буфер обмена: Ctrl+C/X/V; внутри NexusPDF — со стилями (свой формат),
    наружу и снаружи — простой текст (вставка снаружи берёт стиль места
    вставки);
  - отмену внутри ввода (Ctrl+Z/Ctrl+Y) — поверх общей отмены документа:
    после завершения ввода весь ввод — одно действие;
  - доступность: UI Automation (`TextPattern`), чтобы экранный диктор читал
    содержимое и проверки интерфейса находили редактор.
- Плавающая панель — по образцу `InlineTextEditor` (Popup), правая панель —
  расширение существующей панели свойств объекта.
- Выбор шрифта — отдельный контрол (поиск, группы, пометки, названия своим
  начертанием); используется и в правке существующей строки.
- Выделение, перетаскивание, ручки, удаление, копия — через существующий
  механизм выбора черновиков (`ObjectSelection`, `OverlayGeometry`),
  дополненный поворотом и стрелками.
- Щелчок мимо и Esc завершают ввод с сохранением набранного; пустой блок
  при завершении удаляется.
- Клавиши и действия — как в таблице макета, кроме шага стрелок (см. выше).

### Отмена, сохранение, совместимость

- Каждое действие — операция сессии (добавить, заменить, удалить черновик;
  `TextBlockReplacement`) — работает существующая отмена.
- Сохранение — существующий путь записи оверлеев (`SaveWithPageEdits`,
  дописывание для подписанных).
- Экспорт в изображения, печать, OCR видят блок так же, как черновики сейчас.
- `TextOverlay`, штампы, колонтитулы, водяные знаки — без изменений.
- CLI получает команду добавления блока, только если это ничего не стоит;
  иначе — вне этапа.

### Тесты

- Читатель TrueType и каталог шрифтов — на свободных шрифтах из репозитория
  тестов (например, DejaVu или Liberation, лицензии позволяют) и на
  синтетических: пометки кириллицы, `fsType`, `.ttc`.
- Раскладка — модульные тесты: перенос, выравнивания, интервалы, индексы,
  смешанные размеры, длинное слово, пустые абзацы.
- Запись и чтение блока: записать → сохранить → открыть → блок найден и
  совпадает; повторная правка заменяет объекты; блок, изменённый «чужой»
  программой (подмена текста объекта), не открывается как блок; повороты
  страницы 0/90/180/270 и поворот блока.
- Совпадение раскладки с файлом: позиции строк в PDF (`FPDFText`) совпадают с
  раскладкой в пределах допуска.
- Сохранение подписанного документа с блоком — подпись цела.
- Редактор — модель редактирования (вставка, удаление, выделение, стили
  фрагментов, отмена, буфер) отделена от отрисовки и покрыта модульными
  тестами без WPF; положения курсора и выделения — по раскладке.
- Совпадение «экран = файл»: позиции глифов редактора и объектов записанного
  PDF совпадают в пределах допуска.
- Интерфейс — существующими средствами UI-проверок (DesktopAuditProbe в
  release-audit): создание блока щелчком и рамкой, ввод, IME-ввод, смена
  шрифта, перетаскивание, повторное открытие.

## Оставлено исполнителю

- Точный состав плавающей панели при узком окне (что прячется в «⋯»).
- Шаги ручек, привязка к сетке и направляющим — по усмотрению, без ухудшения
  нынешнего поведения выбора объектов.
- Порог предупреждения о большом шрифте (рекомендация: от 10 МБ).
- Формат JSON блока (с версией) и имена параметров метки.
- Как показывать блок с недоступным шрифтом при повторном открытии на другом
  компьютере (рекомендация: открыть с подстановкой и пометить шрифт).
