# Реестр команд

Одна команда — одна запись. Панель, контекстное меню, палитра и горячая
клавиша берут название, значок, сочетание клавиш и правило доступности из
общего дескриптора, поэтому разойтись в поведении они не могут.

## Где что лежит

| Файл | Ответственность |
|---|---|
| `src/NexusPdf.Ux/CommandIds.cs` | Постоянные идентификаторы. Не меняются никогда: на них ссылаются сохранённые настройки. |
| `src/NexusPdf.Ux/CommandDescriptor.cs` | Описание команды: название, значок, категория, группа меню, опасность, пригодность для пальца, правило доступности. |
| `src/NexusPdf.Ux/AppCommands.cs` | Каталог: все команды программы. |
| `src/NexusPdf.Ux/CommandRegistry.cs` | Хранилище и поиск для палитры. |
| `src/NexusPdf.Ux/ContextMenuComposer.cs` | Какие команды показывать для каждого вида выделения. |
| `src/NexusPdf.App.Desktop/Services/Ux/UxCommandHub.cs` | Единственная точка исполнения: `Invoke(id, target)`. |
| `src/NexusPdf.App.Desktop/Views/UxContextMenu.cs` | Сборка меню WPF из дескрипторов. |

## Правило, ради которого всё это заведено

**В каталоге только работающие команды.** `UxCommandHub` в конструкторе
сверяет каталог со своей таблицей обработчиков и падает, если у команды
обработчика нет. Красивый пункт меню, за которым ничего не стоит, обязан
обнаружиться на запуске у разработчика, а не у пользователя.

Обратная проверка — в тестах: `AppCommandsTests` следит, что каждый пункт
контекстного меню есть в каталоге, что у каждой команды есть перевод названия
в обоих словарях и что каждая причина недоступности — реальная строка, а не
латинский ключ.

## Доступность

`CommandDescriptor.Evaluate(SelectionContext)` сначала применяет общие
запреты, потом частное правило команды:

1. идёт длительная операция (`IsBusy`) — всё, кроме безопасных команд, выключено;
2. документ только для чтения (`IsReadOnly`) — то же самое;
3. частное правило команды: нет документа, нет выделения, нет qpdf, автор
   запретил печать и так далее.

Причина недоступности обязательна. Выключенный пункт показывает её подсказкой
(`ToolTipService.ShowOnDisabled`), палитра — прямо в строке. Молча выключенная
кнопка — худший вид интерфейса: пользователь не понимает, что исправить.

## Категории и группы

`CommandCategory` — раздел в палитре. `MenuGroup` задаёт порядок в контекстном
меню, и порядок значений неслучаен:

```
Primary → Quick → Clipboard → Editing → Arrange → Special → Properties → Dangerous
```

«Удалить» лежит в `Dangerous` и поэтому всегда оказывается внизу, а не между
«Копировать» и «Вставить». Разделители ставятся на границах групп
автоматически.

## Множественное выделение

`SupportsMultiSelection` отмечает команды, осмысленные для нескольких объектов.
При выделении нескольких страниц остальные просто не показываются: недоступный
пункт без смысла — шум.

Название получает число: ключ `TitleKey + "Many"` с одним подстановочным
местом, куда подставляется «12 страниц» с правильным окончанием
(`UxCommandHub.CountPhrase`). Если ключа множественной формы нет, показывается
обычное название — выдумывать текст со скобками нельзя.

## Поиск в палитре

`CommandRegistry.Search` ранжирует так:

1. доступные команды выше недоступных (показывать сверху то, что нельзя
   выполнить, — плохой совет);
2. точное совпадение названия (1000) → начало (700) → вхождение (500);
3. ключевые слова: точное (600) → начало (400) → вхождение (300);
4. нечёткое совпадение по буквам подряд (150/100), чтобы «извстр» находило
   «Извлечь страницы».

`Normalize` смешивает «ё» и «е» намеренно: их путают при вводе постоянно.

Ключевые слова — это синонимы пользователя, а не разработчика: «перевернуть»
для поворота, «пейнт» для внешнего редактора, «вымарать» для удаления
конфиденциального, «склеить» для объединения файлов.

## Как добавить команду

1. Идентификатор в `CommandIds`.
2. Дескриптор в `AppCommands.All()` — с ключом названия, ключевыми словами и
   правилом доступности.
3. Строки названия и причин в `ru.json` и `en.json`.
4. Обработчик в `UxCommandHub.BuildHandlers()` — **обязательно**, иначе
   программа не запустится.
5. При необходимости — идентификатор в нужный список
   `ContextMenuComposer.Menus`.

Тесты поймают забытый перевод и пункт меню без команды; запуск программы —
команду без обработчика.
