# Правка объектов на странице

## Что можно выбрать

Щелчок по странице выбирает наложенный объект — то, что добавлено поверх
страницы: надпись, вставленное изображение, рамку, овал, заметку, рисунок от
руки, вымарку.

Выбирается только то, что можно двигать. Разметка текста (маркер,
подчёркивание, зачёркивание) щелчком НЕ перехватывается: она лежит поверх
строк, а читать и копировать документ пользователь будет чаще, чем передвигать
маркер. Снять разметку можно в панели комментариев.

Содержимое самой страницы (текст и картинки исходного PDF) объектами не
считается: для него есть «Править текст» и «Редактировать изображение в
Paint…». Причина в модели: правка содержимого идёт заменой объекта в потоке
страницы, а не перемещением рамки.

## Что с ним можно сделать

| Действие | Как |
|---|---|
| Выбрать | щелчок по объекту |
| Снять выделение | щелчок мимо, Esc |
| Передвинуть | тянуть за рамку; стрелки — по 5 пунктов, Ctrl+стрелки — по одному |
| Изменить размер | тянуть за одну из восьми ручек |
| Дублировать | контекстное меню; копия ложится со сдвигом 12 пунктов |
| Порядок | «На передний план» / «На задний план» |
| Свойства | размер и положение в миллиметрах, место в порядке отрисовки |
| Удалить | Delete или контекстное меню |

Всё отменяется одним Ctrl+Z: перетаскивание — это ОДНА операция, а не
двадцать промежуточных.

## Почему объект прыгает только в конце перетаскивания

Каждая правка страницы перерисовывается движком PDFium: страница заново
собирается в память вместе с несохранёнными правками. Делать это на каждое
движение мыши — значит получить рывки вместо перетаскивания на любом
сколько-нибудь большом документе.

Поэтому во время перетаскивания показывается пунктирная рамка будущего
положения, а сам объект переезжает при отпускании кнопки. Это осознанный
компромисс, а не недоделка.

## Ручки и попадание в них

Ручка на экране всегда одного размера (9 точек) независимо от масштаба
показа: в пунктах страницы её размер пересчитывается. Допуск попадания — 6
точек экрана, тоже пересчитанный: иначе на масштабе 50 % в ручку невозможно
попасть, а промах по ручке означает перетаскивание вместо растягивания, то
есть испорченный объект.

Тянуть можно через противоположную сторону — рамка при этом выворачивается, и
её приводит в порядок нормализация: ширина и высота не бывают отрицательными,
а объект не может стать меньше 4 пунктов, иначе его нельзя будет ухватить.

## Что можно двигать, а что нет

| Объект | Двигать | Растягивать | Почему |
|---|---|---|---|
| Изображение | да | да | |
| Рамка, овал | да | да | |
| Вымарка | да | да | |
| Рисунок от руки | да | да | точки штрихов пересчитываются в новую рамку |
| Надпись | да | нет | точную ширину знает только шрифт; рамка, которая врёт о результате, хуже отсутствующей |
| Заметка | да | нет | значок фиксированного размера 20×20 |
| Разметка текста | нет | нет | привязана к строкам текста |

## Привязка

Перетаскивание привязывается к сетке шагом 10 пунктов. Порог прилипания —
треть шага: если сделать его больше половины, прилипает любое положение и
поставить объект между узлами становится невозможно — сетка превращается в
клетку.

Направляющие важнее сетки: их пользователь ставит осознанно. Механизм
направляющих уже есть в расчётах (`Snapping.Apply`), но линейки, на которых их
ставят мышью, ещё нет — это следующая работа, и до неё направляющих в
интерфейсе не появляется.

## Что не сделано

- Выделение нескольких объектов рамкой и групповые операции.
- Поворот объекта ручкой (поворот есть только у надписи и задаётся при
  создании).
- Направляющие на линейках.
- Выделение и перемещение объектов исходного содержимого страницы.
