# Отчёт о дефектах, найденных измерением

Дата: 2026-08-15, версия 0.16.0-alpha.1.

Здесь только то, что было ВОСПРОИЗВЕДЕНО, а не заподозрено. Для каждого
дефекта указано, чем он был пойман и что теперь удерживает его от возврата.

## Исправлено

### 1. Штрихи рисования писались в PDF мусором

Обёртка PDFiumCore объявляет `FPDFAnnot_AddInkStroke` принимающей ОДНУ точку
по значению, тогда как C-функция ждёт непрерывный массив из `point_count`
пар float. По указателю на единственную структуру pdfium читал чужую память.

Как найден: тест на видимость линии показал 8,4 % тёмных пикселей вместо
ожидаемых 33 %. Дальше — дамп готового файла через `qpdf --qdf`: в
`/InkList` первая точка правильная, остальные — числа вида
`.00000000000000000000000000000000000009403957` и `-22.125641`.

Исправление: прямой P/Invoke в `pdfium.dll` с настоящим массивом.
Удерживает: `InkAnnotationTests.Ink_Stroke_Is_Saved_As_Annotation_And_Is_Visible`
меряет долю тёмных пикселей на линии и вне её.

### 2. Цвет и толщина линии не попадали в рисунок

Свойства задавались ПОСЛЕ добавления штрихов, а внешний вид Ink-аннотации
pdfium строит в момент добавления. Линия рисовалась тонкой и чёрной
независимо от выбора пользователя.

Как найден: тем же измерением доли тёмных пикселей — после первой починки
она подросла с 8,4 % до 11,1 % вместо 33 %.

Удерживает: тот же тест.

### 3. Поворот страницы терял новые типы оверлеев

`OverlayDisplayMapper.ToFrame` переносит координаты из рамки размещения в
итоговую. Для неизвестного типа ветка `default` молча возвращала оверлей как
есть — то есть рисунок оставался в старой рамке.

Как найден: тест «нарисовано без поворота, сохранено с поворотом».

Удерживает: `InkAnnotationTests.Ink_Follows_Page_Rotation_Applied_After_Drawing`
проверяет, что горизонтальная линия становится вертикальной.

### 4. Экранный диктор читал имя класса вместо названия закладки

У каждого узла оглавления автоматизация выдавала
`NexusPdf.App.Desktop.ViewModels.BookmarkViewModel`: заголовок лежит в
шаблоне, а не в тексте элемента дерева.

Как найден: обход дерева UI Automation на живом приложении.

Исправление: `AutomationProperties.Name` с осмысленной строкой
(«название, страница N» или «название, раздел без страницы»).
Проверено повторным обходом: узлы читаются как «1.pdf, раздел без страницы».

### 5. Пустое сообщение об ошибке при отсутствии qpdf

Код просил у словаря ключ `QpdfMissing`, которого в словарях не было —
пользователь увидел бы пустое окно ошибки.

Как найден: `LocalizationCoverageTests` — тест сверяет ВСЕ `Loc.Get`,
`Loc.F` и `{l:Loc}` из кода и разметки с обоими словарями.

Удерживает: этот же тест, плюс второй — на совпадение наборов ключей ru и en.

## Проверено и оказалось НЕ дефектом

- **Битое оглавление в VP BWMPD-2.pdf.** Все 352 закладки показывались как
  «раздел без страницы». Разбор файла через `qpdf --qdf` показал
  `/Dest [ null /FitH 846 ]` — цель в самом документе не задана. Программа
  ведёт себя правильно: не притворяется, что переход возможен.
- **Смещение строки на 1 пт после правки текста.** Рамка объекта описывает
  ЧЕРНИЛА, а у разных букв разные боковые выносы. Точка привязки не меняется.
  Тест сравнивает координаты с допуском 2 пт и объясняет почему.
- **Приложение не закрывается после рисования.** Сработала защита несохранённых
  правок. Подтверждено: после отмены рисунка кнопкой «Отменить» приложение
  выходит чисто (`CLEAN_EXIT=1`).

## Открытые вопросы

- **Неустойчивый тест `SigningTests.Visible_Stamp_Is_Baked_And_Covered_By_Signature`.**
  Один раз упал в общем прогоне и не воспроизвёлся ни в трёх последующих
  полных прогонах, ни при запуске в одиночку. Текст ошибки не сохранился,
  поэтому причина НЕ установлена; правка вслепую не делалась. Вероятные
  направления при повторе: кратковременная блокировка только что записанного
  файла антивирусом и параллельный запуск коллекций xunit. Записано здесь,
  чтобы не потеряться.
