# Модель безопасности

## Активы

Документы пользователя (возможно конфиденциальные), пароли документов,
целостность исходных файлов.

## Угрозы и меры

| Угроза | Мера |
| --- | --- |
| Специально повреждённый PDF эксплуатирует парсер | рендер — PDFium (санитайзится Chromium-процессом разработки); план этапа 3 — вынос в изолированный процесс PdfWorker с лимитами памяти/времени |
| Потеря данных при сохранении | атомарная схема: temp-файл на том же томе → структурная проверка повторным открытием → `File.Replace`; ошибка любого шага не трогает оригинал |
| Утечка содержимого в журналы | в журнал пишутся только пути и метрики; содержимое страниц и пароли не журналируются (пароль живёт в `PasswordBox`/строке на время открытия) |
| Выполнение активного содержимого PDF | JavaScript/Launch-actions не выполняются вовсе: приложение не вызывает соответствующие API PDFium |
| Подмена компонентов | NuGet сверяет SHA-512 пакетов; qpdf будет ставиться скриптом с пином версии и SHA-256 |
| Вторая копия приложения портит настройки | настройки пишутся атомарно (temp+rename); одиночный экземпляр по умолчанию |

## Данные приложения

`%LOCALAPPDATA%\NexusPDF`: `settings.json` (без секретов), `Logs\` (7 дней,
8 МБ ротация), `Recovery\` (зарезервировано), `session.lock` (маркер сессии).

## Ограничения текущей альфы

- Изоляция процесса ещё не включена (см. KNOWN_LIMITATIONS) — не открывайте
  заведомо вредоносные файлы.
- Лимитов на глубину вложенности объектов поверх встроенных в PDFium нет.

Сообщения об уязвимостях: репозиторий проекта, приватно.
