# Исправление отрисовки NexusPDF 0.27.1

Пользователь сообщил, что после действий со страницей версия 0.27.0 показывает «Отрисовка…» бесконечно. Это регрессия изменения списка страниц: небольшие правки заменяют одну модель, сохраняя остальные карточки.

## Воспроизведение

В настоящем WPF под Windows открыт трёхстраничный PDF. Исходная страница отрисовывается и её пиксели совпадают с движком. Добавление заметки заменяет модель первой страницы в уже загруженном шаблоне. WPF меняет DataContext без нового события Loaded, а обработчик запускает отрисовку только на Loaded.

[Проверка исходной версии](https://github.com/skin4ik123/NexusPDF/actions/runs/38151910556) падает после этой операции. Диагностика: видимая карточка — 1; IsAttached — false; Image и ThumbImage отсутствуют; IsRendering — false. Движок не завис: запрос для новой страницы вообще не поступил. Снимок render-regression-failure.png показывает белую страницу с «Отрисовка…» и пустую первую миниатюру.

Прежняя проверка сама вызывала EnsureImage перед снимком. Это обходило неисправный жизненный цикл интерфейса и скрывало ошибку. Теперь проверки ждут обычного автоматического запроса без такого вызова.

## Исправление

1. Полноразмерные карточки обрабатывают смену DataContext и запоминают модель, которую подключили. Unloaded отключает именно её. Включение поведения на уже загруженной карточке также запрашивает изображение.
2. Миниатюры обрабатывают ту же смену контекста. Ожидание видимости снимается при отключении и выгрузке; пустые подписки на прокрутку удаляются.
3. Отменённый запрос не считается активным запросом того же растра. При отмене сбрасывается состояние отрисовки; источники отмены освобождаются после завершения своих задач.
4. Число подключённых представлений учитывается: закрытие старого представления не освобождает изображение, ещё используемое новым. Это необходимо при массовом сбросе списка с переиспользованием моделей.
5. Устаревшие модели после удаления/замены страницы не начинают новые запросы и не публикуют запоздалый результат.

## Проверки

Проверяется автоматический показ после заметки, трёх последовательностей поворот/отмена/повтор/отмена, добавления и изменения текста, удаления наложений, дублирования, удаления и перемещения страниц с отменой каждого действия. После каждой операции пиксели полноразмерного изображения сравниваются с новым рендером текущего PDF.

Отдельно проверяются миниатюры в организаторе, вставка 297 страниц, прокрутка к странице 150 и её правка, возврат и массовый сброс, 16 быстрых изменений и быстрый возврат масштаба. Миниатюра в отдельном окне проверяется без полноразмерного рендера. Проверяются отмена и немедленный повтор запроса в одном ходе UI-потока, два представления одной страницы и освобождение последнего.

Первый исправленный проход настоящего WPF: [38152204048](https://github.com/skin4ik123/NexusPDF/actions/runs/38152204048). Полный выпуск дополнительно проверяет установку, повторную установку, обычное установленное приложение, два поворота и их отмену через UI Automation без переоткрытия PDF, наличие фактических пикселей страницы на экране, CLI и удаление программы.
